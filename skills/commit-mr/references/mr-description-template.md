# 基础 MR 描述模板

这是 `commit-mr` 自己生成的 Review 描述，位于最终 MR 正文最前面。只保留本次改动需要的章节，删除提示文字和空章节，不要把模板本身复制进最终 MR。

```markdown
[相关任务或设计文档](URL) <!-- 没有则删除 -->

## Why this change

{用一句话说明问题，以及发布后可以做什么。}

## Review map

- **Behavior:** {调用方、用户或运维能观察到的变化。}
- **Risk / decision:** {最高风险、关键假设或需要 reviewer 确认的取舍；没有则写“未发现需要特别决策的事项”。}
- **Start here:** `{最值得先看的文件或符号}` → `{下一处证据}`

## Change outline

{用一到三幅最小有效视图讲清实现。每幅图前只写一两句，说明它回答什么 Review 问题。}

```diff
{伪代码、调用树、组件树、文件职责、数据结构或接口契约的变化。}
```

## Special notes

- {迁移、兼容性、刻意省略的范围或令人意外的实现决定。没有内容时删除整个章节。}

## Validation

- **Ran:** `{本次实际执行的命令}` — {观察到的结果}
- **Not run:** {代码库中存在但本次未执行的验证；没有则删除}
- **Recommended:** {仍建议 reviewer 或 CI 补充的验证；没有则删除}
```

## 写作约束

- `Why this change` 恰好一句话。
- `Review map` 面向决策，不重复 Change outline。
- 按行为或因果链组织视图，不按文件逐个总结。
- 代码事实、任务意图和待确认推断不可混写。
- 验证项必须与真实执行记录一致，不能根据测试文件存在就声称已通过。
- 正文保持简洁；原始 diff、长日志和完整测试输出不放入 MR 描述。

## 与仓库模板组合

如果 CodeHub 项目配置了 MR 模板，最终正文按以下顺序组装：

```text
基础 MR 描述

---

填写后的仓库 MR 模板
```

- 仓库模板不存在或为空时，不添加分隔线。
- 保留仓库模板的结构和未勾选检查项。
- 只填写有证据支持的内容；无法回答的字段清除示例或占位值后留空。
- 更新已有 MR 时重新组装完整正文，不在旧正文后重复追加模板。
